# PAIR

**Publicly Accessible Initiative Registry**

A shared, open record of civic initiatives, so anyone can check whether something already
exists before they go looking for it, or go build it.

A volunteer civic project. Not affiliated with, endorsed by, or operated by any government
agency.

## The problem

A lot of people are building civic tools. Very few of them know what the others are building.
The same dashboard gets built four times in three cities while the thing nobody has built yet
stays unbuilt, and a citizen who needs a tool that genuinely does exist has no way to find it.

PAIR is the boring piece of infrastructure that fixes this: one file per initiative, in a
format consistent enough to search across, public enough for anyone to check.

## Who this is for

**If you need something.** You have a question like "can I check what my city spent on road
repairs?" The registry tells you whether a tool for that exists, whether it still works, and
where to find it. If the answer is no, that is useful too, and it gets recorded.

**If you are building something.** Before you start, check whether someone has already done
it. If they have, join them. If they have not, add your initiative so the next person finds
you instead of starting over.

## What is in this repository

This repository holds the standard and the registry data.

```
SPEC.md          the specification: fields, rules, what a validator enforces
CONTRIBUTING.md  how to add or update an entry
initiatives/     one YAML file per initiative
```

The tooling that reads this registry, generates entries and answers questions lives in a
separate repository, [govzeroph/pair](https://github.com/govzeroph/pair). The split is
deliberate: a standard is only a standard if more than one tool can implement it.

## An entry looks like this

```yaml
id: lgu-budget-tracker
name: LGU Budget Tracker
status: live
summary: Shows approved and disbursed budget per local government unit.
capabilities:
  - Check how much budget my city or municipality received this year
  - See what a specific budget line was actually spent on
scope: national
url: https://example.org/budget-tracker
last_verified: 2026-11-12
```

`capabilities` is the field that matters most. It is written from the point of view of the
person using the thing, not the person who built it, because that is how people ask questions.
See [SPEC.md](SPEC.md) for the full field reference.

## Adding an initiative

The short version: generate a draft, check it, open a pull request.

```sh
pair add https://example.org/the-thing   # drafts initiatives/<id>.yaml
pair check                               # validates it
```

You do not need write access to this repository. Everything arrives as a pull request, where
the validator runs again automatically and a maintainer reviews it.

Drafts are generated by a language model and are frequently wrong about details. You are
expected to read and correct the draft before submitting. An entry that overstates what a tool
can do is worse than no entry at all, because someone will rely on it.

You can also write the YAML by hand. The tool is a convenience, not a requirement.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full process.

## Status

Version 0.1.0, draft. The schema may still change in breaking ways. Early entries may need
migration, and that is expected at this stage.

## Licence

CC0 1.0 Universal. The specification and the registry data are both placed in the public
domain, with no conditions at all.

That is deliberate. A registry is only useful if other tools, researchers and agencies can
ingest it without negotiating terms, and an attribution requirement would follow the data into
every downstream system that touched it. Credit is welcome and not required.
